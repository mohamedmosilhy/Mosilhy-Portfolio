## Overview

Fighter Planes is where foundational programming became something immediate and playable. The game asks the player to clear ten-enemy waves while protecting three lives; each completed level increases enemy speed, turning a small rule set into a steadily more demanding arcade loop.

<ProjectGallery />

## Features

- Responsive player movement and projectile firing inside a real-time update loop.
- Collision handling between bullets, enemy aircraft, and the player.
- Ten-enemy stages with escalating speed and level progression.
- Score, lives, game-over, and restart flows.
- Menu and gameplay states that keep transitions separate from active simulation.
- A persisted best score plus custom visual and audio assets.

## Architecture

The LÖVE entry points drive a state-based application structure. Menu and gameplay states own their respective transitions, while reusable source modules represent game objects and supporting components. Update logic advances movement and collisions; draw logic renders the current state; and LÖVE save data preserves the high score across sessions.

## Challenges

Real-time programs expose timing and ownership problems quickly. Projectiles must disappear at the correct moment, one collision must not count repeatedly, state transitions cannot leave stale objects behind, and increasing difficulty must remain playable. Separating game states and object responsibilities kept those rules understandable as the loop grew.

## Lessons learned

This project connected abstract concepts—state, iteration, events, and persistence—to visible behavior. It taught me that satisfying interactions come from many small, consistent decisions: predictable controls, clear feedback, controlled difficulty, and a restart path that feels instant.
