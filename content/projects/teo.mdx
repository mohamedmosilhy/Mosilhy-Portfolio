## Overview

TEO is an architecture-studio portfolio built around visual discovery. Instead of presenting projects as a flat image wall, the experience helps prospective clients move between design work, completed projects, specialties, studio story, and consultation—all while keeping the media itself central.

<ProjectGallery />

## Features

- Dedicated routes for the home, studio story, specialties, and project archive.
- Filtered design and real-project collections with visible result counts.
- Grid and list viewing modes for different browsing preferences.
- A shared image/video viewer with thumbnails, zoom, playback, previous/next controls, and automatic progression.
- Lazy-loaded routes with Suspense fallbacks and an application-level error boundary.
- A consultation flow connected to Google Forms without introducing an unnecessary backend.

## Architecture

The React application separates project content, filtering behavior, and media presentation. Route pages are lazy loaded, a dedicated hook owns project filtering, and reusable gallery components share one media model for both images and video. This keeps a large asset library manageable while allowing the interface to evolve independently from the content.

## Challenges

The difficult part was not rendering media—it was making a large, uneven collection feel coherent. Image and video assets needed consistent navigation, filters had to work across multiple representations, and modal state had to remain understandable as users moved through thumbnails, playback, zoom, and auto-advance. GitHub Pages subpath routing also required careful deployment configuration.

## Lessons learned

Media-heavy products benefit from a shared content model before visual polish is added. Isolating filtering from rendering reduced component complexity, while route-level code splitting protected the initial experience from the cost of a large portfolio. The project strengthened my ability to turn abundant visual content into a deliberate client journey.
