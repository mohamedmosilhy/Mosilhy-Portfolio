## Overview

Relay is a full-stack direct-messaging application designed around a simple promise: conversations should feel calm while the system underneath remains strict about identity, ownership, and data access. Registered users can discover people, start a unique direct conversation, exchange persisted messages, and manage their profile from one responsive workspace.

## Features

- Credentials authentication with registration, login, persistent sessions, and protected routes.
- User search and first-message conversation creation in one workflow.
- Cursor-paginated message history that remains stable as new records arrive.
- Polling-based inbox and conversation refresh without pretending the MVP is fully realtime.
- Profile settings, unread indicators, seeded demonstration data, and responsive conversation layouts.
- Server-side participant checks before every protected conversation read or write.

## Architecture

Relay is organized as a feature-based modular monolith. Authentication, users, and messaging each own their components, schemas, services, server actions, hooks, and types. Prisma models users, conversations, participants, messages, and block relationships in PostgreSQL. TanStack Query manages remote state while route handlers and services enforce authorization at the server boundary.

## Challenges

A messaging interface can appear correct while leaking data through an unprotected endpoint. Every conversation query therefore needed participant verification, not only hidden UI controls. Direct chats also needed a database-level uniqueness strategy, and long histories required pagination that would not drift when new messages arrived.

## Lessons learned

The strongest decision was treating conversation identity as data, not presentation. A deterministic participant key prevents duplicate direct threads; composite participation records make authorization explicit; and last-message timestamps support efficient inbox ordering. Cursor pagination and honest polling produced a dependable MVP without introducing premature realtime infrastructure.
