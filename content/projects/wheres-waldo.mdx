## Overview

Where’s Waldo is a visual search game where players select hidden characters in responsive scenes. The application validates guesses on the server, records completed runs, and displays a separate leaderboard for each scene.

<ProjectGallery />

## Features

- Scene selection and responsive gameplay.
- Click targeting followed by character selection.
- Server-side hit validation without sending stored answer coordinates to the client.
- Completion timing, player-name submission, and scene-specific leaderboards.
- A calibration interface for authoring normalized target centers and radii.

## Architecture

The Next.js App Router application uses feature modules for game, scene, leaderboard, and player concerns. Server Actions fetch scene data, validate guesses, and submit scores. Prisma maps the PostgreSQL models for scenes, characters, target geometry, and scores. Zustand owns cross-component application state while local interaction state remains in React components.

## Challenges

The repository identifies responsive target validation as a primary implementation challenge. Target centers and radii are stored as normalized values so the server can evaluate the same hit area at different rendered image sizes.

## Lessons learned

The documented architectural lesson was to separate local UI state from shared application state and to keep sensitive validation data and logic on the server.
